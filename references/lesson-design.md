# Lesson and Roadmap Design

## Dependency-first planning

A learning roadmap is a graph, not a shopping list.

For each major node identify:

```text
prerequisites → target capability → capability unlocked → proof of learning
```

Prerequisites may be concepts, procedures, representations, or judgment skills.

## Build milestones, not topic piles

Prefer:

```text
learn A+B
→ learner can perform X
→ learn C
→ learner can explain/critique Y
→ integrate in a small authentic task
```

Milestones create observable capability.

## Lesson objective

Each lesson should have one primary objective that can be demonstrated.

Weak:

> Learn derivatives.

Better:

> Explain derivative as local rate of change and estimate its sign and relative magnitude from a graph.

Weak:

> Learn introductions.

Better:

> Write two openings for the same technical article and justify which better serves the intended reader.

## Lesson structure

A robust unit can follow:

1. orientation;
2. motivating problem or artifact;
3. concrete example/phenomenon;
4. intuition/model;
5. rule or principle;
6. terminology/formalism;
7. guided variation;
8. independent practice/production;
9. boundary, misconception, or critique;
10. retrieval summary.

Do not include all steps mechanically when the lesson is simple.

## Difficulty ladder

Use the ladder appropriate to the task.

### Procedural

```text
worked example → missing step → guided problem → independent problem → unfamiliar variation
```

### Conceptual

```text
example → explanation → prediction → contrast → boundary → transfer
```

### Productive/open skill

```text
model analysis → imitation → constrained production → feedback → revision → independent production → critique
```

### Memorization

```text
meaning/context → active recall → discrimination → spaced recall → use
```

## Project selection

A learning project should have a high ratio of target learning to incidental work.

Good properties:

- quick or observable feedback;
- natural incremental milestones;
- few unrelated dependencies;
- mistakes are interpretable;
- extensions are obvious.

A project may be software, an essay, a proof set, a research memo, a conversation challenge, an experiment, or another authentic product.

## Roadmap output

When the learner asks for a roadmap, include:

- destination capability;
- prerequisite map;
- ordered stages;
- proof-of-learning task per stage;
- authentic milestones/projects;
- optional deeper branches;
- review points when retention matters.

Use `../templates/knowledge-map.md` or `../templates/study-plan.md` when helpful.
