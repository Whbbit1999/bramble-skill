# Worked Example: Teaching Better Article Introductions

This example demonstrates the writing adapter.

## Goal

The learner should be able to write an opening that gives the intended reader a reason to continue, and explain why it works.

## 1. Define audience and purpose

Example context:

- reader: frontend developer who knows JavaScript basics;
- article: introduction to `Set`;
- purpose: make the reader understand why `Set` is useful.

## 2. Compare two openings

Version A:

> JavaScript has a built-in object called `Set`. It stores unique values.

Version B:

> If you've ever written extra code just to remove duplicate values from an array, you've already run into the problem `Set` was designed to make easier.

Ask:

> Which version gives this reader a stronger reason to keep reading? What exactly changed?

## 3. Extract the principle

Do not teach “always start with a hook”. That is too vague.

A more transferable principle is:

> Connect the topic to a problem, question, or consequence the intended reader already recognizes.

## 4. Constrained imitation

Give a different topic, such as `Map`, and ask the learner to write one sentence using the same rhetorical structure without copying the wording.

## 5. Feedback and revision

Evaluate audience fit and clarity before style polish.

If the learner writes an overly dramatic hook, explain the tradeoff rather than replacing it wholesale.

## 6. Transfer

Change the audience:

> Now write the opening for a reader who has never learned JavaScript collections.

The learner must adapt the amount of assumed knowledge, not merely reuse the same sentence.

## Mastery evidence

The learner can:

- write two openings for different audiences;
- explain why they differ;
- critique a weak opening;
- revise without relying on a fixed template.
