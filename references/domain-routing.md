# Domain and Learning-Task Routing

Use two axes: **task type** and **domain**. Do this silently unless exposing the classification helps the learner choose a path.

## Axis A: learning-task type

### 1. Conceptual understanding

The learner wants to know what something is, why it works, or how ideas relate.

Default pattern:

```text
phenomenon → intuition → relationship → terminology → boundary → prediction
```

Proof of learning: explain, predict, distinguish, or apply.

### 2. Procedural skill

The learner wants to perform a method: solve an equation, use a grammar form, execute a workflow, calculate, configure, or follow a technique.

Default pattern:

```text
worked example → decision points → guided attempt → faded support → independent attempt → variation
```

Do not mistake copying steps for procedural mastery.

### 3. Causal / explanatory reasoning

The learner wants to understand why an event, mechanism, outcome, or pattern occurred.

Default pattern:

```text
outcome → candidate causes/mechanisms → evidence → interactions → counterfactual/boundary → explanation
```

Avoid single-cause stories when the subject is genuinely multi-causal.

### 4. Analytical / critical judgment

The learner wants to compare arguments, evidence, approaches, designs, interpretations, or quality.

Default pattern:

```text
criteria → examples → comparison → justification → counterexample → calibrated judgment
```

Separate factual constraints from value judgments or stylistic preferences.

### 5. Generative / productive skill

The learner wants to write, speak, design, prove, code, compose, or otherwise create.

Default pattern:

```text
model → imitation → constrained production → feedback → revision → independent production
```

Do not overtake authorship. Let the learner produce whenever the goal is learning the skill.

### 6. Memorization / retrieval

The learner needs durable recall: vocabulary, formulas, dates, terminology, definitions, facts.

Default pattern:

```text
meaning/context → retrieval cue → active recall → spacing → discrimination → use
```

Do not use rereading as the main strategy.

### 7. Project / integration

The learner wants to combine several capabilities into an authentic task.

Default pattern:

```text
goal → capability decomposition → milestone → just-in-time teaching → artifact → reflection
```

Minimize incidental complexity.

### 8. Assessment / preparation

The learner wants to know what they can currently do or prepare for an exam/interview.

Default pattern:

```text
representative task → evidence of reasoning → classify gap → targeted practice → retest
```

Do not reteach before a diagnostic unless requested.

## Axis B: domain

Choose the most relevant adapter:

- software/computing → `../domains/programming.md`
- mathematics/statistics → `../domains/mathematics.md`
- writing/rhetoric → `../domains/writing.md`
- second-language learning → `../domains/language-learning.md`
- physics/chemistry/biology and empirical science → `../domains/natural-sciences.md`
- history/philosophy/economics/social sciences/general conceptual knowledge → `../domains/conceptual-subjects.md`

For a topic not covered exactly, select the closest adapter based on the learner's required cognitive work rather than the subject label.

Examples:

- formal logic can borrow from mathematics + conceptual subjects;
- technical writing can combine programming + writing;
- statistics can combine mathematics + natural sciences when data/evidence interpretation matters;
- economics can combine conceptual subjects + mathematics when modeling is central;
- music theory can often use mathematics-like pattern teaching plus productive-skill practice.

## Routing priority

When several routes are plausible, prioritize:

1. the learner's explicit goal;
2. the task they actually need to perform;
3. the dominant reasoning pattern;
4. the nominal subject label.

Example:

> “我要学会写数学证明。”

This is not merely mathematics. It is mathematics + productive skill + reasoning. Teach proof construction, not only theorem content.

## Switching routes during a session

A session may change route.

Example:

```text
understand derivative concept
→ learn derivative procedure
→ solve problems
→ explain an unfamiliar graph
```

The tutor should change activity accordingly instead of staying locked in explanation mode.

## Unknown or mixed domains

If no adapter fits perfectly:

- use the general Learning Tutor rules;
- identify the target capability;
- borrow only the domain rules that genuinely help;
- avoid forcing terminology or exercise types from an unrelated domain.
